# Instructions for Returning

_This tutorial is an early draft. It teaches current behavior where the repository can execute the experiment and marks every
later destination as a roadmap._

The ship's manual used the word *return* for six different operations. It did not consider this a defect.

Then the return procedure failed.

This series begins with one text file and no assumed programming or quantum knowledge. You will learn Wheeler while an apprentice
aboard the courier *Vela* learns why the ship cannot certify its journey home. The book inside the story gives neither of you a
technical word before an experiment creates a need for it.

You do not need physics, linear algebra, complex numbers, binary arithmetic, or previous programming experience. You need a
Wheeler source checkout, JDK 26, a text editor, and a terminal.

## Begin the voyage

1. [Return to which state?](00-return-to-which-state.md) opens on the destination without explaining it.
2. [Write the first instruction](01-write-the-first-instruction.md) turns ordinary text into a Wheeler artifact.
3. [Ask the machine to act](02-ask-the-machine-to-act.md) executes that artifact and reads the smallest useful report.
4. [Give the machine one thing to remember](03-one-thing-to-remember.md) introduces a named state value.

These pages form a pilot, not a complete release unit. The index links only pages with finished draft content. Later parts remain
unlinked until their experiments and explanations exist.

## The language grows with you

The crew begins with broad words that work until the machinery stops being ordinary. The experiments split those words into more
precise ones.

| Early word | Distinctions the voyage will earn |
| --- | --- |
| return | inverse, rewind, uncompute, adjoint, replay, retry |
| result | state, outcome, observation, sample, distribution, evidence |
| same | equal value, restored state, repeated preparation, replayed record |
| linked | dependent, correlated, product state, entangled |
| random | unknown, sampled, probabilistic, seeded, noisy |
| proof | exact execution, sampled evidence, structural certificate, theorem |

A lesson introduces a term in five moves:

1. You observe something concrete.
2. You try to describe it with words you already have.
3. An experiment shows that one old word covers two different things.
4. The lesson gives the distinction its accepted name.
5. You use the new term to make a prediction or tighten a claim.

The text never hides a required definition for dramatic effect. It delays the name, not the explanation.

## The book's three ledgers

Selected lessons end with three short lists.

**Words earned** names concepts that the experiment now supports.

**Words sharpened** narrows an ordinary word that remains useful.

**Phrases retired** records language that would preserve a false model.

The ledgers do not award points. They show how your language changes as your explanations improve.

## The shape of the journey

The complete route has five broad passages:

1. Build ordinary state and discover why an overwrite can prevent an exact return.
2. Learn trials, probability, signed contributions, amplitudes, interference, and one qubit.
3. Combine two qubits, distinguish correlation from entanglement, and reuse eligible reversible work coherently.
4. Give interference a bounded algorithmic job through oracles, search, and the quantum Fourier transform.
5. Leave ideal simulation, meet target limits and noise, and return with evidence that says exactly what happened.

The destination is not a machine that reverses everything. Measurement, external effects, commit, replay, and retry do not become
one universal undo operation. The destination is the ability to state what returned, how it returned, what record remains, and what
the evidence permits you to claim.

## How fiction and experiments fit together

The voyage provides questions, characters, setbacks, and payoffs. Wheeler source and checked output settle the technical claims.
A character may guess wrong. The compiler, runtime, tables, and declared evidence show why.

The ship does not travel along several physical routes at once. Quantum operations do not provide faster than light messages,
conscious measurement, or magic propulsion. The fictional machinery never changes Wheeler semantics or supplies a fact that the
experiment cannot support.

Each command runs from the repository root. The [development guide](../reference/development.md) explains the current JDK and local
build requirements.
